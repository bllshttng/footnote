# state-roots-baseline.txt - the ratchet for `fno doctor lint state-roots`.
#
# Epic x-3d21 R4 rules that every fno state access resolves against a DECLARED
# root. Eighty-four sites already build one by hand. Migrating them is not
# this gate's job (the Rust journal sites are x-1571's, the duplication half is
# x-6f9f's), so they are held here with an owner and a reason while the gate
# stops the next one appearing.
#
# FORMAT, tab-separated:  RULE<TAB>path<TAB>key<TAB>owner<TAB>reason
#   RULE   A = a hand-built `<root>/.fno/<state file>` path.
#          B = a zero-argument lru_cache/cache over a reader that resolves a
#              state root (x-3d21 R5).
#   key    rule A: the state filename. rule B: the function name.
#   owner  the node that owns draining it, or `unowned`.
#
# The key is (RULE, path, key) and deliberately carries NO line number: a line
# number moves on every unrelated edit above it, so a line-keyed baseline
# churns, and churn teaches people to regenerate the file, which is how a
# ratchet stops ratcheting. The stated cost is that two hand-built paths for
# the same state file in one module drain as one entry.
#
# THE GATE FAILS IN BOTH DIRECTIONS, and the second is the load-bearing half:
# a hit not listed here fails, AND a line listed here whose site no longer
# matches fails with "fixed, remove this line". Without the second direction a
# drained line becomes a permanent exemption.
#
# There is no --update flag on purpose. Adding a line is a deliberate act with
# an owner attached, in a diff a reviewer reads.
