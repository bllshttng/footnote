# Per-disposition ceiling for check-no-direct-graphql-pr-read.sh. One row:
# <disposition> <max callers>. Measured 2026-08-20.
#
# Read as a ceiling, never equality. Removing a caller passes. Adding one
# raises a count and goes red, which is the case worth a human read: the
# blanket-allow buckets accept anything by path, so a count is the only
# tripwire on a new raw caller landing there.
#
# Prose is not counted. That means the `documentation` disposition, and it also
# means any .md row whatever its disposition: the disposition rule only catches
# a #- or //-prefixed line in a code file, so markdown slipped through it. All
# 11 worker-proxy-or-hook rows measured on this tree were prose in skills/*.md,
# which is why that bucket has no row here. A real executable caller under
# skills/ would make the disposition appear with no baseline row, and the gate
# refuses an unknown disposition rather than accepting it.
#
# KNOWN BLIND SPOT, stated rather than discovered later. A count cannot see a
# same-PR swap: delete one routed call site under cli/src and add a raw one,
# and fno-process-proxy is still 110, so this passes. The sha256 inventory pin
# this replaced did catch that shape, and it was dropped anyway because it went
# red on every comment reword over 194 rows, which is how it ended up ignored
# and unwired. The unclassified assertion still catches a raw caller in any
# root that is not blanket-allowed. Closing the swap case needs a set
# comparison of caller PATHS beside this ceiling, not the whole-body digest
# back.
#
# Raising a number is a deliberate act: say in the PR body why the new caller
# is routed rather than raw.
