# problem

Name the user, the problem, the goal, and the non-goals before you design anything. A node that names no user gets one invented on paper, and the plan then optimizes for nobody.

Write one job story: in <situation>, I want <motivation>, so I can <outcome>. If the story reads flat, the premise is thin. Go back to the node brief before the plan.
