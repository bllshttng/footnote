# Ship and promise: draining reviews before `<promise>`

Read this when the PR is up and you are deciding whether to promise. It is the operational detail behind the spine's "drain reviews FIRST" rule: what to read, in what order, and which checks gate the promise. The three-way turn-ending contract itself stays in SKILL.md ("How to end every turn").

**Pre-push local review:** Run `fno do target request-self-review` without `--pr` on the final local HEAD before `/fno:pr create`. It pins the branch and HEAD against the origin base (using `refs/remotes/origin/HEAD`, falling back to `main`) and refuses detached HEADs. It sends one leading-slash payload naming `<branch> HEAD <sha> against origin/<base>` through `--to-self --raw`, without `--comment`; the payload invokes `$fno:review` on Codex or `/fno:review` elsewhere, inline in the target worker session. No PR exists yet. Count review rounds before push: one clean round is enough; findings buy one fix and one more request. A rebase with an unchanged code delta carries the attestation. The `--pr <PR_NUMBER>` form handles post-push requests and refuses unless local HEAD matches the PR head. A `started` result hands the session to the inline lane and waits for its clean marker; a `queued` Codex mux result ends the turn at the boundary. `unconfirmed` and `refused` stop the ship path. Never replace a missing native result with advisory prose. `review.max_rounds` applies across the PR; when status reads `rounds_exhausted: true`, request no more review or attestation, and require review coverage `covered` before the promise. Read the Review-cap gate for the final disposition.

<IMPORTANT>
CI green is NOT "ready to promise". A posted optional-bot review (`chatgpt-codex-connector`) is part of the review you must drain BEFORE `<promise>` even when `required_bots` is empty. Do NOT infer "done" from `gh pr checks` + `reviewDecision` alone: the codex bot posts `COMMENTED` reviews that carry real inline findings while leaving `reviewDecision` EMPTY, and a `*-bootstrap` CI check is the bot's setup job, not its review. You MUST list the posted reviews and read every one's inline comments (`gh api repos/{owner}/{repo}/pulls/<n>/comments`), not just its body. That exact shortcut (green checks + empty decision = ready) has shipped unaddressed findings; it is the failure this section exists to prevent.

Drain reviews FIRST - as early as they post, not after CI goes green. A finding read at first-post folds into the fix round already in flight; a finding read only at green forces a fresh push that re-runs CI from scratch (the ping-pong this ordering avoids). CI is meant to be tackled locally ahead of time (hermetic preflight), so the remote CI round-trip is a confirmation, not your feedback loop - for code fixes and review fixes alike.
</IMPORTANT>

**Watch for posted optional reviews WHILE CI is polling - read them at first-post, not only at green.** Every wait round that reads `fno do pr status <n>` should also list posted reviews and read any new one immediately, so a real finding folds into the fix round already in flight instead of adding a post-green round. Rides the existing poll cadence - one extra cheap read per round, no new loop, no higher frequency. On each poll: project the review list (`gh pr view <n> --json reviews --jq '.reviews[] | {id, author: (.author.login // "ghost"), submittedAt}'` - the `// "ghost"` fallback keeps the read from crashing on a deleted/ghost author) and compare ids against a cursor file `.fno/scratchpad/pr-<n>-reviews-seen.txt` (the manifest `scratchpad_path`, keyed by PR number, deduped by review id - NEVER the immutable manifest; a missing/malformed cursor is treated as empty, re-reading is harmless). For each NEW id: read it in full - its body (from the review object, e.g. `gh pr view <n> --json reviews --jq '.reviews[] | select(.id=="<id>") | .body'`) AND its inline comments (`gh api repos/{owner}/{repo}/pulls/<n>/comments`, which returns every inline review comment on the PR; that endpoint carries the inline comments only, never the review body, so both reads are needed), because a codex review carries its findings in inline comments under a boilerplate body, so a body-only read silently misses everything - then print ONE line (`new optional review from <bot>: <k> findings`) and classify each finding: *actionable* -> fix it in the current round (the fix rides the next push that was already going out); *stale/inapplicable* -> note why and leave it for the backstop's judgment. A review posted against an EARLIER commit is still read in full and classified against current HEAD (stale placement != stale finding). Quiet by default: a poll round with no new id prints nothing. Degrade, never abort: a failed `gh` read skips the watch that round (CI polling continues); an unwritable cursor proceeds without persisting and warns once. Same never-wait-for-unposted rule as the backstop (a silent or usage-limited bot never blocks - the watch reads only what exists), and the same `--no-external` / config skip.

**Optional posted reviews:** An empty gate means external review is optional. Read reviews that already posted after CI turns green. Take one snapshot of PR reviews from optional reviewers (`chatgpt-codex-connector` or `config.review.peers` logins) with `gh pr view <n> --json reviews,comments`. Read every `COMMENTED` review and its inline comments with `gh api repos/{owner}/{repo}/pulls/<n>/comments`. Do not rely on `reviewDecision` or `gh pr checks` alone. Codex can post findings with an empty `reviewDecision`. A `*-bootstrap` check only covers bot setup. Resolve unaddressed findings before `<promise>`. Do not wait for reviews that have not posted. Silent or usage-limited bots do not block. Skip this read under `--no-external` or config.

**Run the configured local review gate before you promise.** The three review-gate flavors compose independently: `config.review.required_bots`/`github_apps` (GitHub App bots, drained above), `config.review.reviewers` (local attestation), and `config.review.peers` (local attestation when identity-free, posted CLI review when identity-backed - see the per-carrier split below). loop-check already *reads* all three - but the producer side is yours: when `reviewers` or `peers` is non-empty, `/target` must RUN the named reviewers on the **final shipped HEAD** and emit BEFORE `<promise>`, or loop-check requires an attestation nothing produces and the loop hangs with no explanation. Empty config (today's default) makes this whole step a no-op, so a fresh install never blocks. `--no-external` scopes NARROWLY: it skips only *external* posting (the drain of posted bots, and identity-BACKED `peers` posts), NEVER a local attestation - and that includes the identity-free `peers` composite, which is local despite living under the `peers` key. loop-check's `no_external` gates only its GitHub-login reads and still requires `reviewers_all_attested` independently (loopcheck.rs, test `no_external_still_honors_reviewers_gate`), so skipping a configured local reviewer would leave its gate permanently unmet and hang the loop forever (the exact failure this feature exists to prevent). Reuse the existing producers - there is no new gate machinery here, only invocation:

- **`reviewers`** (`fno config get review.reviewers`): run every configured reviewer on the final shipped HEAD. Emit its head-pinned `review_attestation`. loop-check requires it even with `--no-external`.
  - `sigma` -> RETIRED. Init refuses a config that names it and identifies the replacement. Do not run a panel for it.
  - `declare` uses `/fno:review declare` for explicit self-certification.
  - `code-review` uses `/fno:review` on final HEAD. Its emit step works on every harness without hook support.
  - Native `/code-review` on Claude and `/review` on Codex remain the user's choice.
  - Claude's `hooks/code-review-attest.sh` emits after a clean empty findings report. Triggers include `PostToolUse(ReportFindings)` and `SubagentStop`.
  - Codex's hook emits from a `Stop` payload with one same-turn structured completion. Accept `exited_review_mode` or `item_completed` with `ExitedReviewMode`.
  - Both hooks require an object-valued findings array equal to `[]`.
  - The Codex attester runs before `target-stop-hook.sh`. It needs no second step.
  - If the lane and hook are unavailable but review is clean, recover with `bash skills/review/scripts/emit-attestation.sh code-review`. Confirm the attestation before promising. Never use recovery to attest over findings.
  - **A name outside those three is a project-registered reviewer** (`config.review.reviewer_registry`, keyed by that name). It is NOT an error and MUST NOT be skipped: run the descriptor's `invocation` verbatim, then `bash skills/review/scripts/emit-attestation.sh <name>`. Read the descriptor with `fno config get review.reviewer_registry`, and `fno config doctor` lists each configured reviewer with the rung it asserts. The helper takes any name, so there is no new producer machinery - but nothing else emits for you, and skipping this leaves a gate only this reviewer can clear. An `asserts: invocation` reviewer attests that it RAN at this HEAD; footnote does not read its output, so a `pass` verdict here claims invocation, not approval. If its skill did not run, do not attest - say so and stop, exactly as with a peer post that did not happen.
- **`peers`** (`fno config get review.peers`) - TWO carriers, resolved per entry by whether an identity is configured. Read which one applies BEFORE running anything: the wrong carrier emits nothing, the gate stays unmet, and the loop wedges with the work already done. `fno do target start`'s `done-when:` line names whichever gate is actually armed and its exact producer command.
  - **Identity-free** (no `config.review.peer_identity` and no per-entry `identity` - the shape `/fno:setup` writes) - every such entry collapses into ONE composite LOCAL reviewer named `peer`, cleared by a head-pinned `review_attestation` exactly like a `reviewers` entry. Run `/fno:review peer <provider> --attest` for a SINGLE eligible cross-model provider (no `<pr#>`: `--attest` pins to the current HEAD and needs no PR, GitHub account, or PAT - the same producer `fno do target start` prints); that one pass clears the whole composite. **`--no-external` does NOT skip this** - `no_external` gates only loop-check's GitHub-login reads, and this gate is local, so skipping it leaves a gate permanently unmet (the same trap spelled out for `reviewers` above). `--post` is the WRONG carrier here: with no identity the helper fails loud, produces no attestation, and the gate holds.
  - **Identity-backed** (`peer_identity`, or a per-entry `identity`) - this IS external posting, so it skips under `--no-external` / config (loop-check skips the peers LOGIN gate then). For each such entry run `/fno:review peer <pr#> <provider> --post`; it posts under that machine account (a distinct GitHub account) and gates on the login. If the identity or its PAT is unset the helper fails loud and the gate stays UNMET - surface that reason and stop, never fake a post that did not happen.
  - Never mix carriers for one entry (same rule as `/pr check` Step 0b): `--attest` satisfies the local composite reviewer key, `--post` satisfies an explicit GitHub login.
- **Head-pinning is load-bearing.** Emit once per review, on the head it read. A later fix can leave coverage uncovered below the cap. The stop gate or status command then names the owed round. Never copy an earlier verdict onto a new head. Each new head it lands on spends a round.
- **A configured reviewer IS the request to run it.** A harness whose system prompt says not to dispatch subagents unprompted (the background-session default) must not read that as forbidding a configured `reviewers` entry: the user asked for that reviewer when they put it in config, and declining leaves a gate only that reviewer can clear, so the loop wedges with the work already done. `fno do target init` refuses such a run up front, and `fno config doctor --review` reports which reviewers this session can drive. The default reviewer (the fno lane) runs inline as ordinary tool calls, so the unprompted-dispatch concern never applies to it.
- **The lane runs once on the final HEAD.** A push does not move it. The fno lane's attestation certifies the head its review read. A rebase with an unchanged code delta carries the attestation. Fixes take a new-head request while the budget lasts. Nits and non-blocking findings do not hold the gate. An unaddressed blocker holds it below the cap.

**Termination (the round budget).** A blocking finding is cleared by fixing it. The next review covers the fix delta. Nothing else clears it on your own signature. A non-blocking finding needs no action to clear the gate. Answer it in thread or skip it with a note. At the cap, decline what you do not fix with a recorded reason, request no round, and merge on green CI. Read the full rule in the review skill's Review-cap gate. The round budget bounds the fno review lane's rounds and the Codex P1/P2 fix-and-rerun cycles. Cleanup-class material belongs to `/fno:review cleanup` and never buys a round.

**Codex review:** Every target runs the fno review lane inline in the worker's own session on the final HEAD. No harness-native background command or spawned reviewer belongs to the ship flow.
