# Law limitations

## Known Limitations and Deferred Work

- **Invocation is the authority. The door is the law LANE, never the `operator` VALUE.** `require_marked_caller` answers `chat_attested` off `resolve_self_identity`. That call walks process ancestry. So any process descended from a harness session can record. That includes an agent's own Bash call, with no user-shaped text anywhere. Measured: a bare `fno inbox law set` from an agent Bash call records a row that `_decision_lane` reads as `law`. Before ruling d-e1eec854 that same call was refused. The operator ruled for one step on 2026-08-29 with the risk named. This is the trade, written down rather than discovered later.
- **What the door does NOT open, measured on the same session.** `authority_source: operator` stays refused. `_resolve_decider` raises `RefusedAuthorityError` on the `if agent and authority_source == "operator"` branch. Name that branch correctly. `enforce_origin_floor` and `MAX_AUTHORITY_BY_ORIGIN` are NOT what stops it. The law command declares no origin. So the floor sees `None` and returns it unchanged. The cap lookup is then skipped. The cap is read only under an `operator` claim anyway. A reader who checks `authority_source` can always tell the two apart. A reader who checks only the LANE cannot.
- **The narrower mail shape is the one that is impossible to detect. That was measured, not assumed.** Every transcript under this machine's claude project directory was scanned. 2173 user turns carrying an `<fno_mail>` envelope are recorded with `promptSource: "typed"`. 2439 are recorded with `origin: {"kind": "human"}`. Both harness-supplied fields report human and typed on an injected turn. `--raw` strips the `<fno_mail>` envelope, which is the only remaining marker. So there is no field to refuse on. A refusal built on one of those fields is theater.
- **A session records its own kind. It never retires the operator's.** `require_marked_caller` lets a resolved session win, so an in-session caller never resolves `operator`. Two guards follow from that. `retract_decision` requires `authority_source` to be exactly `operator`. Supersession of an `operator` row is refused from a `chat_attested` caller. The second guard is what makes the first mean anything. Every reader that filters `--state live` stops seeing a superseded row. So a supersession of the operator's law retires it under another name. A session can still supersede another `chat_attested` row.
- **A session cannot clean up after itself.** A row minted by accident or by injection stays. The minting session cannot remove it. The store is machine-wide and append-only. Withdrawing such a row needs an attended terminal outside every harness session.
- **What the retired ceremony actually bought.** The staged proposal, the content hash and the one-shot receipt refused a bypass-mode session. They refused a headless session too. They did not refuse an attended chat. An attended chat approved the prompt without reading the hash. Mail lands as an attended chat. So the ceremony blocked the honest path and not the dishonest one. Retiring it gave up less than its four steps cost.
- **Attribution survives the trade.** A chat recording carries `authority_source: chat_attested` and never `operator`. That value reads in the **law** lane at or after `AUTHORITY_LANE_CUTOVER`. It stays distinct from `operator`. So a reader can always tell a chat recording from a person at a terminal. A chat recording still cannot prove a human origin. It no longer claims to.
- **A caller that nothing marks is still refused.** No harness session and no terminal means no decider. `fno inbox law set` then exits 3 and records nothing. Law is never inherited by silence.
- **The store is machine-local.** A stranger who clones the repository must obey some rules. Those rules do not reach that person from here.
